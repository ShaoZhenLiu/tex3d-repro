## 3. 目标布局：路径保持方案（核心设计）

09 的 `/data` 空间紧张，数据实际落 /data6，但**所有脚本/jobs 文件/软链/.pth 都硬编码了 `/data/shaozhen.liu/...` 绝对路径**。解法：真实数据放 /data6，在 /data/shaozhen.liu 下建**同名软链**，绝对路径零改写：

```
/data6/shaozhen.liu/tex3d-mig/code               # 代码（tex3d/deps/openpi/tex3d-ws）
/data6/shaozhen.liu/tex3d-mig/envs               # 四个 venv
/data6/shaozhen.liu/tex3d-mig/model              # 7 个核心模型
/data6/shaozhen.liu/tex3d-mig/uv-python          # venv 的 CPython 解释器（⚠️ 不放 home）
/data6/shaozhen.liu/tex3d-mig/torch_extensions   # nvdiffrast JIT 缓存（⚠️ 不放 home）
/data/shaozhen.liu/code  -> /data6/shaozhen.liu/tex3d-mig/code
/data/shaozhen.liu/envs  -> /data6/shaozhen.liu/tex3d-mig/envs
/data/shaozhen.liu/model -> /data6/shaozhen.liu/tex3d-mig/model
```

**用户明确要求（2026-10-12）：迁移内容与一切环境安装均不进 /home。** 因此 venv 解释器放 /data6 的 uv-python/，拷贝后把各 venv 的 `bin/python*` 软链和 `pyvenv.cfg` 的 `home=` 行重指向它（见 §5-2）；JIT 编译缓存用 `TORCH_EXTENSIONS_DIR` 指到 /data6（见 §5-1）。

**状态：目录骨架与三个软链已于 2026-10-12 建好**（09 上 `ls -la /data/shaozhen.liu/` 可见 code/envs/model → /data6/...）。尚未传输任何数据，等用户确认后执行 §4。

（09 的 /data/shaozhen.liu 现存内容只有 python_project 和几个 wheel，软链为新增，不冲突。）
如此 `runner.sh jobs_eval_gpu3.txt` 等可原样运行；唯一要改的是 GPU 编号（见 §6）。

## 4. 传输方案（已就绪，等指令执行）

  $DST/code/

  /data/shaozhen.liu/model/openvla-7b-finetuned-libero-spatial \
  /data/shaozhen.liu/model/openvla-7b-finetuned-libero-object \

  ln -sfn /data6/shaozhen.liu/tex3d-mig/uv-python/python/cpython-3.10.5-linux-x86_64-gnu/bin/python3.10 $d/python3.10
  sed -i "s|^home = .*|home = /data6/shaozhen.liu/tex3d-mig/uv-python/python/cpython-3.10.5-linux-x86_64-gnu/bin|" /data/shaozhen.liu/envs/$v/pyvenv.cfg

d=/data/shaozhen.liu/envs/tex3d-pi0/bin
ln -sfn /data6/shaozhen.liu/tex3d-mig/uv-python/python/cpython-3.11.14-linux-x86_64-gnu/bin/python3.11 $d/python
ln -sfn /data6/shaozhen.liu/tex3d-mig/uv-python/python/cpython-3.11.14-linux-x86_64-gnu/bin/python3.11 $d/python3
ln -sfn /data6/shaozhen.liu/tex3d-mig/uv-python/python/cpython-3.11.14-linux-x86_64-gnu/bin/python3.11 $d/python3.11
sed -i "s|^home = .*|home = /data6/shaozhen.liu/tex3d-mig/uv-python/python/cpython-3.11.14-linux-x86_64-gnu/bin|" /data/shaozhen.liu/envs/tex3d-pi0/pyvenv.cfg

## 5. 环境适配清单（迁移后在 09 上做）

1. **nvdiffrast JIT 重编（唯一的硬适配）**：4090=sm_89、A100=sm_80，缓存的 torch_extensions 不能用。首次运行 nvdiffrast 相关脚本前：
   ```bash
   export PATH=/opt/rh/devtoolset-9/root/usr/bin:$PATH   # gcc9，替代系统的 4.8.5
   export TORCH_CUDA_ARCH_LIST="8.0"                      # 为 A100 编译
   export TORCH_EXTENSIONS_DIR=/data6/shaozhen.liu/tex3d-mig/torch_extensions  # JIT 缓存不进 home（骨架已建）
   export CUDA_VISIBLE_DEVICES=0 MUJOCO_EGL_DEVICE_ID=0 MUJOCO_GL=egl PYOPENGL_PLATFORM=egl
   ```
   首跑会现场 JIT 编译（几分钟），产物落 09 自己的 ~/.cache/torch_extensions。
2. **uv python 软链核对**：§4-⑤ 已把各 venv 的 `bin/python*` 与 `pyvenv.cfg` 重指向 `/data6/shaozhen.liu/tex3d-mig/uv-python/python/cpython-{3.10.5,3.11.14}-linux-x86_64-gnu/`。迁移后抽查：`readlink -f /data/shaozhen.liu/envs/tex3d-openvla/bin/python` 应落在 /data6 下，`.../bin/python -V` 应出版本号。
3. 若某 venv 仍异常（理论上不应，glibc 已验证兼容）：退回重建路线 = `tex3d-deps/setup_tex3d.sh` 去掉代理两行后重跑（09 直连外网，比 41 当初还省事），坑全在 ENV_NOTES.md。
4. π0 官方栈（如需）：`serve_policy.py` 首推理 371s 惰性编译，先跑 `rlinf_eval/warmup_probe2.py <port>` 预热（交接总结 §四）。

## 7. 风险与注意事项

- **⚠️ 09 系统时钟是 EDT 时区**（实测 `date` 显示 Oct 11 23:12 EDT = 北京时间 Oct 12 11:12，差 12 小时）。读 09 上的文件 mtime、日志时间戳、job 队列起止时间时**先做 −12h 换算**，否则会像本次一样误判"目录昨天就没了"。
- **/data4 有 I/O 错误**（读 `/data4/shaozhen.liu` 报 Input/output error），该盘勿用，建议报管理员；迁移目标 /data6 不受影响。
- **2026-10-12 清理记录**：按用户清单删除 home 缓存 121G（保留 huggingface/hub、token、modelscope）、hf_models 7 个模型 ~99G（保留 sft_models；72B 137G 为用户自删）、/data5 五项 180G。清理后 /home 133G 空闲、/data 244G、/data5 344G、/data6 1.1T。
- **/home 禁放策略**：迁移内容、venv 解释器、JIT 缓存一律在 /data6（§3、§5）；后续在 09 装 uv/conda 等工具时也注意设 `UV_PYTHON_INSTALL_DIR` 等变量指向 /data6。
- **41 侧负载 93**：rsync 读盘会进一步加重（已用 ionice 缓解）；传输期间勿在 41 上跑评测。
- **09 内存压力**：GPU 闲但系统内存曾被他人占到 251G/237G。OpenVLA 评测单进程 ~13GB 显存 + 数十 G 内存，若 available < 40G 先观察/协调再开任务。
- **不删 41 任何数据**：41 是事实源头（source of truth），迁移完成且 G1–G5 全绿后再考虑清理（/data 13T 空闲，无压力）。
- **迁移密钥善后**：09 的 authorized_keys 里 `sz41-migration` 那行，迁移收尾后可删（不影响 Windows→09 登录，那条走的是另一把钥匙）。
- **速度参考**：A100 80G 单卡显存翻倍 → OpenVLA 攻击训练（41 上 35.6GB/进程）可在单卡双跑；评测（13GB）可 3-4 进程并行，6 个评测预计比 41 上 ~4.5h 明显更快。
